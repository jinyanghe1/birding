### 技术选型结论
- **三级漏斗**：osxphotos 元数据 → MegaDetector V6 ONNX（判有无动物，~30ms/张，免费砍 85%）→ 连拍去重+选片（砍一半）→ **Agent 视觉识别**（300–600 张，含时空先验）
- 已证伪/否决的方案：
  - BirdNET / Perch / BirdMAE **全是音频模型**，不能处理照片
  - Apple Vision `VNClassifyImageRequest` 只有 bird/heron/owl 等粗标签，无鸟种
  - SpeciesNet 实测缺白头鹎/画眉/麻雀/普通翠鸟等中国常见种
  - `Hakureirm/bird-id-mcp` 实测 0 star / 无 LICENSE 文件 / 无精度数据，只作参考
  - iNat 官方权重不公开；timm iNat21 是 CC BY-NC 且无中文名
- 备选兜底：懂鸟商业 API ¥100/1万次（Top1 85%/Top5 96%），仅用于低置信度复核
- 定时任务用 **launchd**（cron 在 macOS 无 TCC 归属，易失败）

### 关键工程决策与实测
- **MegaDetector 权重直链**（Zenodo，非 HF）：
  `https://zenodo.org/records/15398270/files/MDV6-yolov10-c.pt?download=1`（5.5MB）
  `https://zenodo.org/records/15398270/files/MDV6-yolov9-c.pt?download=1`
  从 `PytorchWildlife/models/detection/ultralytics_based/megadetectorv6.py` 源码里扒到的。
- **绕开 PytorchWildlife 的 `__init__`**：它会强拖 timm / yolov5 / soundfile（约 2GB）。
  改为 `ultralytics.YOLO(本地 .pt)` 直载，依赖链干净。
- **MPS benchmark（32 张真实照片）**：
  mps@640 = 23ms/张｜**mps@960 = 44ms/张（采用）**｜cpu@640 = 188ms｜cpu@960 = 389ms
  → MPS 比 CPU 快约 8 倍。ultralytics/MPS 非线程安全，必须串行提交。
- **L1 阈值定 0.20 且不能提高**：置信度是双峰分布（要么 0 要么 ≥0.2）。
  人工看图校验发现 conf=0.20 的样本里就有真鸟，提高阈值会漏。
  低置信度误报（人物/画作/截图/龟）交给 L3 Agent 过滤，成本可接受。
- **L0 关闭了 PNG 截图过滤**：默认规则会误杀 1,831 张无 GPS 的 PNG，
  其中可能混有导出的真实鸟照。多检测只需 80 秒，误杀却要全量重扫 → 保召回。
- `nohup ... &` 在本环境会被静默杀掉，长任务要用 Bash 工具的 run_in_background。

### 全库扫描实测（15,415 张）
- L0：跳过 199 张（too_small 92 / no_local_image 112 等），待检测 14,816
- **L1：14,816 → 2,586 检出动物（17.5%），耗时 11 分 42 秒**
- **L2：2,586 → 1,826 连拍组 → 保留 2,122**（只砍 18%，因为 1,507 组都是单张）
  - 说明 L1 误报不少：队列里出现「中国美术馆 41 张」「国家博物馆 28 张」，
    明显是雕塑/画作被当成动物。这部分只能靠 L3 过滤。

### L3 识别：最终采用「本地开源模型」而非 Agent 视觉
**关键约束：当前会话的模型不支持读图**（Read 图片返回 "does not support images"），
所以「Agent 看图识别」在本会话无法执行。改用开源模型，也符合用户说的
「如果有更好的开源实现，也可以考虑一下」。

- 模型：Hakureirm/bird-id-models（HF）
  - `convnext_bird_cls.onnx` 138MB，输入 [N,3,224,224] 输出 [N,10753]
  - `yolo_bird_detect.onnx` 12MB，输入 [1,3,640,640] 输出 [1,5,8400]
  - `labels_cn_10753.txt` 提供中文名
  - ⚠️ `s1v2_bird_cls.onnx` 下载损坏（66K，应 38MB），已弃用
- **必须用「YOLO 框鸟 → 裁剪 → 分类」，不能整图直推**：
  整图直推时鸟占比小，中心裁剪根本不含鸟，准确率崩掉（top1 只有 2-5%）。
  加检测裁剪后 top1 能到 79%/48%。
- 速度 85ms/张（CPU），2,154 张跑了 5 分 20 秒。
- **结果：822 张检出鸟，212 张高置信，610 张待复核。**

### 置信度分档（重要）
| 档位 | 观测数 | 物种数 | 可信度 |
|---|---|---|---|
| ≥0.45 | 196 | 36 | 可靠，界面默认展示 |
| 0.30–0.45 | 69 | 33 | 勉强 |
| <0.30 | 520 | 379 | 噪声（出现"非洲泽鹞""艾草松鸡""紫头鹦鹉"等中国不可能有的种）|

→ 因此加了 `config.UI_MIN_CONF = 0.45`，界面/CLI 默认只展示高置信档，
  低置信的进「待复核」队列，留给多模态模型或人工。

### 外链 URL 实测结论（重要，避免走弯路）
- **eBird 物种页 `ebird.org/species/<code>` 需要登录**（curl 302→CAS），但浏览器内已登录则正常
- **Cornell BOW `birdsoftheworld.org/bow/species/<code>` 免登录 200**，无效 code 返回 404 → **用它校验 code**
- **birdsoftheworld.org 不支持 HEAD 请求**（HEAD 一律失败），必须用 GET 且只读前 2KB
- **birdsoftheworld.org 拦截自定义 UA**，必须带浏览器 UA
- eBird code 生成启发式（连字符名取首字母+末词前3位）对多词名有效，但猜不准的都靠 BOW 校验兜底
- **Xeno-canto v2 API 已废弃**，v3 需注册拿 key；Macaulay Library 无公开 API → 声音只能给搜索外链
- **懂鸟 dongniao.net / birdreport.cn 均无可用外链格式**，不给链接
